高危案例 A · 长期半开连接（握手风暴）

设备 07（无线 AP）连续向本机并不提供服务的 784 端口发起半开连接，窗口内 51,493 次，占该设备同期全部连接的 74.8%

主体：设备 07（无线 AP）　窗口：2026-09-24 01:52 → 2026-09-27 02:42

窗口内形态 · 窗口内按小时（0–23 时）的连接数分布

逐项数字证据

指标数值口径 / 说明
半开连接数（:784 → 主路由）51,493窗口内该设备发出的 784 端口连接流水
该设备同期全部连接数68,884同窗口、该设备全部出向连接
占比74.8%784 端口占该设备同期连接的比例
正向报文 TCP 标志仅 SYN（无 ACK）flags 取值分布：2→51,493
反向报文 TCP 标志仅 RST+ACKflags 取值分布：20→51,493
窗口内累计字节 / 报文3,092,760 B / 51,546 个总字节极小 → 符合「只发 SYN、不传数据」的半开特征
全期 784 端口连接总数179,257该设备整个采集期内累计
本次窗口2026-09-24 01:52 → 2026-09-27 02:42来自 keep_windows 人工标注窗口

判定依据

  • 正向全部是 SYN-only：三次握手的第一步发出后无人应答，连接从未建立。
  • 反向全部是 RST+ACK：对端明确拒绝——等于确认 784 端口上根本没有服务在监听。
  • 占比高达七成以上：不是偶发探测，而是该设备固件的常态重试行为。
  • 逐条可复核：把 keep_windows 里 ref='A' 的窗口取出，按 src/dport 计数即可复现以上全部数字。

可复核 SQL 口径

SELECT count(*) FROM flows WHERE src=<该 AP> AND dport=784 AND ts BETWEEN <窗口>; -- 得 51,493

高危案例 B · 单小时端口扇出爆炸 + 同日上行峰值

设备 01（手机）在单个小时内向 11,317 个不同外网目的端口发起连接；同日（2026-09-27）上行流量峰值约 9.48 GiB、外网对端 27,055 个

主体：设备 01（手机）　窗口：2026-09-27 00:00 → 2026-09-28 00:00

窗口内形态 · 扇出 Top 小时（外网目的端口数）

逐项数字证据

指标数值口径 / 说明
全期单小时扇出峰值11,317 个外网端口2026-09-27 18:00–59，15,042 条连接 / 9,501 个外网对端
人工标注的扇出爆发小时5,521 个外网端口2026-09-25 20:00–59，7,966 条连接 / 5,318 个外网对端
峰值日上行流量9.48 GiB2026-09-27 全天该设备出向字节（外网口径）
峰值日外网对端数27,055 个同日不同外网目的地址数
峰值日连接总数67,680 条同日外网出向连接条数
参考口径（更早快照）5,930 个端口 / 26,969 个对端 / 9.48 GiB作品文档记录值；本页为构建时 SQL 实取，差异来自采集仍在持续、库内数据增长

判定依据

  • 单个小时向数千个不同端口发起连接：普通应用不会做出这种「广撒网」的端口访问模式。
  • 紧接着同一台设备出现持续数小时的上行高峰：与 PCDN / 直播类上行共享行为的时间形态一致。
  • 扇出（端口 × 对端）与上行量两个维度同时异常，单指标阈值会漏，故靠多指标同离群升档。
  • 逐条可复核：按小时对 src 分组、count(DISTINCT dport) 排序；按日对 src 分组求和 bytes 即可复现。

可复核 SQL 口径

SELECT strftime('%Y-%m-%d %H',ts,'unixepoch','localtime') h, count(DISTINCT dport) FROM flows WHERE src=<该手机> GROUP BY h ORDER BY 2 DESC LIMIT 1; -- 得 11,317

中危案例 C · 平板凌晨入向流量离群

设备 08（平板）在凌晨 02:00 出现单小时入向流量离群，约为其自身留一基线的 2148 倍

主体：设备 08（平板）　窗口：2026-09-29 02:00 → 2026-09-29 02:00

窗口内形态 · 该设备 24 小时（0–23 时）入向字节分布（log1p 纵轴）

逐项数字证据

指标数值口径 / 说明
离群小时2026-09-29 02:00该设备凌晨时段（00:00–06:00）入向字节最大的一个小时
该小时入向流量1,865,208,590 B（1.74 GiB）features_hourly.bytes_in
该设备全期小时中位数871,033 B稳定基线：中位数
留一基线（log1p 中位数还原）868,327 B剔除该小时后剩余小时、在 log1p 尺度取中位数再还原
相对留一基线的倍数约 2148 倍观测值 ÷ 留一基线
人工标注同类窗口2026-09-27 02:00 · 980,783,822 Bkeep_windows 人工标注窗口内单小时入向；按同一口径约为基线的 1130 倍（参考文档记约 1,304 倍）
参考口径约 1,304 倍作品文档记录值；本页按构建时数据与上文口径实算，倍数随基线口径略有差异
同设备其他凌晨离群小时15 个凌晨时段入向流量超过基线 20 倍的小时数——说明这不是孤例，而是该设备反复出现的形态

判定依据

  • 凌晨本应是流量低谷，该设备却在此时出现单小时入向洪峰——与作息不符。
  • 用留一基线而非全期均值：把被检验小时从基线里剔掉，避免离群值自己抬高基线。
  • log1p 尺度抑制长尾：流量分布右偏严重，线性均值会被大值主导，取 log1p 后中位数才稳。
  • 逐条可复核：对 features_hourly 按 ip 过滤、取 bytes_in 序列即可复现中位数与倍数。

可复核 SQL 口径

SELECT hour_ts, bytes_in FROM features_hourly WHERE ip=<该平板> ORDER BY bytes_in DESC LIMIT 1; -- 该窗口得 1,865,208,590 B
